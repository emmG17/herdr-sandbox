# Domain docs

The repo uses a single context: `CONTEXT.md` at the root and architecture decision records in `docs/adr/`.

Before exploring code for a task, read `CONTEXT.md` and ADRs relevant to that area. These files may not exist yet; continue when absent. Create them when domain terms or decisions are resolved.

Use the terms defined in `CONTEXT.md` when naming concepts in issues, code, and tests. If a needed term is missing, check the codebase’s language and record the gap for domain modeling.

If proposed work conflicts with an ADR, identify the ADR and explain the conflict before changing direction.
